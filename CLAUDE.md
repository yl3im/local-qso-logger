# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Local QSO Logger — a single-page amateur-radio contact (QSO) logger. Vanilla HTML/CSS/JS, **no build step, no dependencies, no backend**. The static files (`index.html`, `style.css`, `app.js`, `favicon.svg`, `manifest.webmanifest`, `service-worker.js`, a single `i18n.js` bundle that carries all 28 language dictionaries, and a single `contests.js` bundle that carries all 68 contest configs) are the whole app.

## Running / testing

There is no build, lint, or test tooling. **A local dev server is always running on <http://localhost:8080/>** — use that for every manual check and every headless-browser probe. Do **not** spin up `python3 -m http.server` (or any other server) on a different port. `file://` opens also work if you need to sanity-check the service-worker guard, but the preferred verification path is the already-provided HTTP server.

Verify changes manually in the browser. To reset app state, clear `localStorage` for the origin (key `local-qso:v1`).

## Hard constraints (the point of the project)

- **All logic is client-side. Data lives ONLY in browser `localStorage` (key `local-qso:v1`).** No backend, no network calls, no telemetry, no external persistence — do not introduce any.
- Service-worker registration in `app.js` is guarded by `location.protocol.startsWith("http")` so `file://` opens stay clean. That guard is load-bearing — keep it.
- `*.adi` files and `.claude/` are gitignored. The repo contains large sample `.adi` files for manual testing; don't commit new ones.
- **Never `git commit` or `git push` without an explicit request in the current turn.** Complete the code changes, run the local verification, and stop — leave everything in the working tree so the operator can review and stage manually. "Commit and push" (or similar) has to come from the operator; a task that says "implement X" does not authorise a commit.

## Architecture (app.js)

All code is one IIFE in `app.js`, organized in labeled sections. Key pieces:

- **State** (`load`/`save`): `{ logs, selectedId, theme, lang }` persisted as JSON. `theme` is `"day"|"night"` (day default); `lang` is one of `SUPPORTED_LANGS = ["en","ru","de","fr"]` (en default; invalid values fall back to en on load). Each log: `{ id, name, qsos[] }`. Each QSO has always-present `{ id, call, date, time, band, mode, propMode, rstSent, rstRcvd }` plus optional keys attached only when non-empty: `submode`, `stationCall`, `operator`, `myGridSquare`, `gridSquare`, `comment`, and — SAT only — `bandRx`, `satMode`, `satName`. Old saved logs may carry removed `callsign`/`locator` fields — ignored on load. `editingId` is module-level and **not** persisted.
- **i18n** (`t()`, `applyLanguage()`): all 28 language dictionaries live in the single bundled `i18n.js` at repo root. Each language is a self-contained IIFE that assigns `window.I18N[<lang>]` a flat key→string map; blocks are delimited by `// ==== <lang> ====` header comments — grep for one to jump to that language's section. `t(key, ...args)` looks up the active dict, falls back to English, then to the key; positional placeholders `{0}`, `{1}`, ... are replaced with args. `applyLanguage()` walks `[data-i18n]` / `[data-i18n-html]` / `[data-i18n-placeholder]` / `[data-i18n-aria-label]` elements to update labels, then re-applies state-dependent strings (theme toggle, qso-submit). The language `<select>` in the header has flag-emoji-prefixed native-name options ordered English first, then Latin-script alphabetical (Čeština → Svenska), then Cyrillic-script alphabetical (Беларуская → Українська), then Greek (Ελληνικά); US flag stands in for English. Adding a new string means adding a key to all 28 language sections in the one file; falling back to English keeps things from blowing up if you forget. Bundling into one file saves ~23 KB gzipped and 27 HTTP requests on first load vs the previous per-file layout — translation files are highly repetitive so gzip compresses the whole set far better than 28 separate streams.
- **Rendering**: `render()` = `renderLogList()` + `renderDetail()` + `save()`. Table rows are built newest-first; Edit/Delete buttons are at the *start* of each row (touch priority). Cell text is set via `textContent`, never `innerHTML`, to avoid injection from callsigns/log names.
- **Dates/times are UTC** (amateur-radio convention; `getUTC*`). Stored as ISO `YYYY-MM-DD` + `HH:MM:SS`. The table date column renders via `Intl.DateTimeFormat` (user locale); storage/ADIF stay ISO. New QSOs auto-stamp current UTC at submit; edit mode uses whatever the user typed.
- **Modes** (`MODE_GROUPS`): full ADIF MODE→SUBMODE taxonomy rendered as a `<select>` with `<optgroup>`s. `MODE_NO_PARENT_OPTION` (DYNAMIC/FSK/MTONE) marks parents selectable *only* via a submode. **Two-field ADIF model:** `q.mode` is always the parent MODE (e.g. `SSB`, `MFSK`), and `q.submode` is the specific SUBMODE (e.g. `USB`, `FT4`) — attached only when the operator picked a submode from the dropdown. Submitting the form derives both from the raw selection via `modeParent()` and `SUBMODE_TO_PARENT`. The table shows `q.submode || q.mode`. Legacy state where `q.mode` held a submode value is auto-migrated on load (split into `q.mode` + `q.submode`). ADIF export writes `MODE`/`SUBMODE` directly from the two fields; import reads them separately and derives a missing parent from a known submode via `SUBMODE_TO_PARENT`. `VOICE_PARENTS` drives `rstDefaultFor()` → "59" for voice, "599" otherwise (AM kept in the set for legacy data though it's no longer in the dropdown).
- **Propagation mode** (`PROP_MODES`): full ADIF Propagation Mode Enumeration (§ III.B.13) as a `<select>` whose first option is empty (matching the spec convention that PROP_MODE is absent for typical HF QSOs). Stored on `q.propMode` as the ADIF code (e.g. `SAT`, `RPT`); the dropdown shows `CODE — description` for clarity. Consumed on import and re-emitted on export via `PROP_MODE` in `KNOWN_ADIF_FIELDS`.
- **Satellite fields** (`SAT_NAMES`, `SAT_MODES`): when `q.propMode === "SAT"`, the QSO form reveals three satellite-only fields via a `.is-sat` class on `#qso-form` (CSS: `.sat-only { display: none }`, `.qso-form.is-sat .sat-only { display: flex }`): `SAT_NAME` (dropdown, ~110 entries), `SAT_MODE` (dropdown of AMSAT mode designations split into "modern" two-letter codes — `SAT_MODES_MODERN` — at the top and legacy single-letter codes — `SAT_MODES_DEPRECATED` — at the bottom via `<optgroup>`s; each entry is `[code, uplinkBand, downlinkBand]`, and `SAT_MODES` is the flat concatenation used by the change handler for band lookup), and `BAND_RX` (dropdown, same options as `BAND` with empty first). Selecting a `SAT_MODE` auto-adjusts `BAND` = uplink and `BAND_RX` = downlink. **Sat-only properties (`q.satName / q.bandRx / q.satMode`) are only attached to the QSO when `propMode === "SAT"` — non-satellite QSOs don't carry these keys at all.** Editing a QSO from sat to non-sat (or vice versa) adds or deletes them as needed. `GRIDSQUARE` and `MY_GRIDSQUARE` are **not** sat-only — they live in the QSO-data and Station-data blocks respectively, are always visible, and are attached only when non-empty. On import, sat properties are only attached when the source ADIF record actually contained them. Legacy imported `SAT_MODE` values (like "U/V") not in the enum are preserved via a one-off `<option>` appended when the QSO is opened for edit.
- **Callsign → country flag** (`callsignCountry` + `CALL_PREFIX` + `isoToFlag`): 2-letter-then-1-letter prefix lookup → ISO 3166-1 alpha-2 → regional-indicator emoji. `CALL_PREFIX` is curated, **not exhaustive** — unknown prefixes render no flag. Strips portable suffixes (`/P`, `/M`, `/MM`, `/QRP`, `/digit`, etc.); for prefix-portable calls like `9A/M0NCG` picks the shorter side as the operating prefix. Test coverage against real data with the sample `YL3IM.adi`. Single-letter entries at the end of the map must not collide with 2-letter blocks above.
- **ADIF export** (`buildAdif`/`adifField`): declares `ADIF_VER 3.1.7` (via `ADIF_VERSION`), `PROGRAMID local-qso`, `PROGRAMVERSION` (from `APP_VERSION`), and `CREATED_TIMESTAMP` (UTC `YYYYMMDD HHMMSS` via `nowAdifTimestamp`). Per-QSO emits `CALL/QSO_DATE/TIME_ON/BAND/MODE/SUBMODE/PROP_MODE/GRIDSQUARE/BAND_RX/SAT_MODE/SAT_NAME/RST_SENT/RST_RCVD/COMMENT/STATION_CALLSIGN/OPERATOR/MY_GRIDSQUARE` — optional fields (`SUBMODE`, station data, grids, comment, sat props) are skipped by `adifField()` when absent. After the typed fields, every entry in `q.extras` is re-emitted verbatim — that's how the app round-trips ADIF fields it doesn't model in its UI (NAME/FREQ/DXCC/QSL_*/etc.). Field length in the tag is byte length via `TextEncoder`. Downloads via Blob.
- **ADIF import** (`parseAdif`/`parseAdifRecord`/`importAdif`): always creates a **new** logbook named `Imported YYYY-MM-DD HH:MM UTC` — never merges; filename is ignored. Parser scans at the **byte level** (`Uint8Array` from `TextEncoder`), so the ADIF field-length prefix is treated as a UTF-8 byte count per spec (multi-byte content in text fields like COMMENT slices correctly). `parseAdif` returns `{header, records}` so the header block is inspected too — an `APP_LQ_CONTEST_ID` in the header (emitted by our own contest exports) makes the new log a contest log of that contest, and per-record `APP_LQ_*` fields matching the contest's exchange schema are pulled into `q.contestExchange`. `KNOWN_ADIF_FIELDS` names the fields consumed by the typed model; anything outside that set (and outside the imported contest's exchange fields) is stashed on `q.extras` for lossless re-export.
- **Contest logbooks** (`CONTESTS` + `contests.js` — a single bundled file): a logbook can optionally be a contest log via `log.contestId`. Missing key ⇒ regular logbook, existing UX unchanged. `contests.js` is one hand-maintained file at the repo root carrying all 68 contest configs. Each config is a self-contained IIFE that writes to `window.CONTESTS[<id>]` a `{name, shortName, windows[], bands[], modes[], exchange[], duplicateRule, cabrillo}` object. Blocks are delimited by `// ==== <id> ====` header comments — grep for one to jump to that contest's section. Bundling saves ~42 KB gzipped over the previous 68-files layout (contest configs are highly repetitive, so gzip compresses the whole set far better than 68 separate streams) and cuts HTTP requests by 67 on first load. **68 configs ship**, grouped as: CQ family (`cqww-{ssb,cw,rtty}`, `cq-wpx-{ssb,cw,rtty}`, `cq-160-{cw,ssb}`, `cq-m`); ARRL family (`arrl-dx-{ssb,cw}`, `arrl-fd`, `arrl-10m-{dx,w}`, `arrl-160m-{dx,w}`, `arrl-rtty-ru-{dx,w}` — asymmetric contests ship separate `-dx` / `-w` variants for the two exchange perspectives); European regional (`iaru-hf`, `iaru-r1-fd`, `wae-{ssb,cw}`, `baltic`, `sp-dx`, `nrau-baltic-{ssb,cw}`, `eu-hf-championship`, `lz-dx`); Russian club / RadioSport (`russian-dx-{dx,ru}`, `russian-ww-rtty`, `rus-ww-mm`, `gagarin`, `rfc-{cw,ssb}`, `rrtc`, `asrucamp`, `dzcup`, `rdac`, `raem`); Central/Eastern EU asymmetric — each with host + DX variants (`okom-dx-{cw,ssb}-{dx,ok}`, `ha-dx-{dx,ha}`, `yo-dx-hf-{dx,yo}`, `ur-dx-{dx,ur}`, `ur-rtty-{dx,ur}`, `ref-{cw,ssb}-{dx,f}`, `bfrr-{cw,ssb}-{dx,ew}`, `ari-dx-{dx,i}`, `9a-cw-{dx,9a}`, `cnc-cw-{dx,ea}`); other (`all-asia-{cw,ssb}`). Adding another contest = paste a new IIFE block into `contests.js` at the right alphabetical position; no `index.html` change, no `service-worker.js` change, no `app.js` change needed. The `exchange` array declares one field per input the operator sees in the QSO form's *Contest exchange* block (built dynamically by `renderContestExchangeFields`). Field types are `text`, `number`, and `serial` (auto-incrementing, readonly). `sticky: true` fields prefill from the previous QSO's value. Values are stored per-QSO in `q.contestExchange` (only non-empty keys). The `.contest-only` block is toggled by `.is-contest` on `#qso-form`, mirroring the `.sat-only`/`.is-sat` pattern. Contest-aware `updateDupIndicator()` honours `duplicateRule` (`per-band-mode` / `per-band` / `per-day` / `off`) — still informational, never blocking. `updateContestWarnings()` posts a non-blocking chip when the current UTC falls outside `windows` or when band/mode is outside the contest's declared legal set.
- **Cabrillo export** (`buildCabrillo`/`exportCabrillo`, `CABRILLO_MODE` + `CABRILLO_BAND_KHZ`): contest logs get a second export button (`Export .cbr`) alongside `.adi`. Emits Cabrillo v3: `CONTEST:` from `contest.cabrillo.contest`, header fields pre-filled from the first QSO's station data (`CALLSIGN` / `GRID-LOCATOR` / `OPERATORS`) plus the rest from `log.contestSubmission` (edited in the collapsible *Submission-info* panel), then one `QSO:` line per contact whose exchange columns come from the contest's `cabrillo.sentTemplate` and `cabrillo.rcvdTemplate` (each is a list of exchange-field ids). `rst_sent`/`rst_rcvd` are special-cased to the QSO's top-level `q.rstSent`/`q.rstRcvd`. `CLAIMED-SCORE: 0` is emitted verbatim — scoring is v2. `ADDRESS` and `SOAPBOX` may be multi-line and are emitted one header line per non-empty source line. `CABRILLO_BAND_KHZ` maps our band names to a representative TX-kHz value since we don't record dial freq.
- **Cabrillo import** (`parseCabrillo`/`importCabrillo`/`cabrilloContestMatch`/`freqKhzToBand`/`CABRILLO_MODE_REVERSE`): reverses the emit pipeline. The single `Import log file` button auto-detects format via `detectAndImport` — `START-OF-LOG:` in the first 500 chars → Cabrillo; `[REG1TEST;1]` → EDI (alerts user; not yet supported); otherwise ADIF. `parseCabrillo` returns `{header, qsoLines}`: header is a flat `{KEY: value}` map with multi-line `ADDRESS` / `SOAPBOX` values joined with `\n`; each `QSO:` line becomes a whitespace-split token array. `importCabrillo` resolves the contest by `CONTEST:` header against `contest.cabrillo.contest`; ties (e.g. `ARRL-10` matches both `arrl-10m-{dx,w}`) are broken by (1) matching the first QSO's Cabrillo mode letter against each candidate's `modes[]`, (2) matching total column count against each candidate's `sentTemplate.length + rcvdTemplate.length`, (3) preferring the id ending in `-dx` (matches YL3IM's Latvia-based DX use), (4) alphabetical first. Column layout is `QSO: freq mode date time mycall [sentLen] theircall [rcvdLen]` (6 + sentLen + rcvdLen tokens). `rst_sent`/`rst_rcvd` template positions hydrate `q.rstSent`/`q.rstRcvd`; everything else goes into `q.contestExchange`. `freqKhzToBand` finds the closest midpoint match in `CABRILLO_BAND_KHZ`. `CABRILLO_MODE_REVERSE` maps `PH`/`CW`/`RY`/`DG` to ordered mode candidates; first entry present in the contest's `modes[]` wins. Header fields matching `contest.cabrillo.headerFields` populate `log.contestSubmission`; `CALLSIGN` / `GRID-LOCATOR` / `OPERATORS` populate every QSO's `stationCall` / `myGridSquare` / `operator`.
- **ADIF ↔ contest round-trip**: on export, if `log.contestId` is set the header carries `APP_LQ_CONTEST_ID` and each QSO's exchange fields emit under the contest config's `adifField` mapping (all in the `APP_LQ_*` namespace). On import, the header's `APP_LQ_CONTEST_ID` (if present and known) is used to rehydrate `log.contestId` and split per-record `APP_LQ_*` fields into `q.contestExchange`. Unknown contest ⇒ contest fields land in `q.extras`, still lossless — so a foreign or forgotten export round-trips without data loss.

## UI / behavior decisions (don't "fix" these — they're intentional)

- Duplicate-callsign indicator is informational only; duplicates are allowed.
- Log name defaults to `Log YYYY-MM-DD HH:MM UTC` when blank.
- Band & mode are sticky across consecutive QSOs in a session.
- Switching logs or deleting the current log cancels an in-progress edit.
- Inline rename (Rename button): Enter commits, Escape cancels, blur commits.
- Deleting the last logbook auto-creates a fresh one (`ensureAtLeastOneLog`).
- Theme via `data-theme="day|night"` on `<html>`; day theme in `:root`, night overrides under `[data-theme="night"]`. `color-scheme` is set so native date/time pickers follow the theme.

## CSS (style.css)

- `.panel { min-width: 0 }` is load-bearing on mobile — without it the table's `min-width` propagates up the grid and overflows the viewport. The table scrolls horizontally inside `.qso-table-wrap` on narrow screens.

## Service worker

`service-worker.js` is cache-first and precaches the static assets on install, evicting old caches on activate. Bump the `CACHE` constant when shipping new asset versions, or clients keep serving stale files.
