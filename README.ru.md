Аппаратный журнал QSO для радиолюбителей, уважающий вашу конфиденциальность и работающий целиком в браузере. Без учётной записи, без сервера, без отслеживания, без аналитики — ваши журналы хранятся только в `localStorage` браузера и никогда не покидают ваше устройство.

Автор: [YL3IM](https://www.qrz.com/db/YL3IM). Сайт проекта: [qso.lv](https://qso.lv).

## Возможности

- Несколько журналов; у каждого свой список QSO-связей.
- **Контестные журналы** опциональны — выберите одно из 68 встроенных соревнований при создании журнала. Форма QSO получает специфический блок *Контестный обмен*, обнаружение дубликатов соблюдает правило соревнования, а *Экспорт .cbr* создаёт файл Cabrillo v3 для подачи заявки наряду с обычным экспортом ADIF.
- Действия с журналом: создание, переименование, удаление, импорт файла журнала (ADIF или Cabrillo — формат определяется автоматически), экспорт в ADIF (`.adi`), плюс *Экспорт .cbr* (Cabrillo v3) для контестных журналов. Повторный импорт файла `.cbr`, ранее экспортированного приложением, восстанавливает его как тот же контестный журнал.
- Форма QSO разбита на три блока: **Данные станции** (позывной станции, позывной оператора, собственная локаторная ячейка) остаётся неизменным между QSO; **Режим работы** (режим распространения, спутник, режим, спутниковый режим, диапазон, диапазон приёма) со спутниковыми полями, появляющимися только при режиме распространения *Спутник*; и **Данные QSO** (позывной вызываемой станции, локатор вызываемой, дата/время UTC при редактировании, комментарий, RST отправлено, RST принято).
- Полная таксономия ADIF `MODE` → `SUBMODE` в выпадающем списке режимов — выберите родительский режим (`SSB`, `MFSK`, …) или перейдите сразу к конкретному подрежиму (`USB`, `FT4`, …); приложение хранит оба поля согласно ADIF, а таблица отображает конкретный подрежим, если он есть.
- Полное перечисление режимов распространения ADIF (SAT, RPT, EME, ES, MS, Aurora и т.д.) в виде выпадающего списка.
- Полный каталог спутников AMSAT (~110 аппаратов) и двухуровневый выпадающий список **Sat mode**: предпочтительные двухбуквенные коды восходящего/нисходящего канала вверху (LU, LV, SX, UU, UV, VA, VU, VV) и устаревшие однобуквенные обозначения (A/B/J/K/L/R/S/T/U/V/W/X) сгруппированы как *устаревшие* внизу. Выбор спутникового режима автоматически устанавливает восходящий `BAND` и нисходящий `RX band`.
- Редактирование и удаление любой QSO-связи (с подтверждением при удалении).
- Разумные значения по умолчанию: сегодняшняя дата/время UTC заполняются заранее, RST по умолчанию зависит от режима (59 для голосовых, 599 для CW/цифровых), постоянные Данные станции + диапазон + режим + режим распространения между последовательными QSO (только поля каждой связи — позывной, локатор, комментарий, RST — очищаются после каждого *Записать QSO*).
- Живой индикатор дублирующего позывного (информационный — дубликаты разрешены).
- Столбец флага страны, определяемый по префиксу позывного (охватывает ≥99 % распространённых любительских префиксов, включая переносные позывные типа `9A/M0NCG`).
- Отображение даты в соответствии с локалью в таблице QSO; хранение и вывод ADIF остаются в формате ISO.
- Интерфейс на **28 языках** (английский плюс 22 на латинице, 5 на кириллице и греческий); селектор с флаговыми эмодзи в заголовке.
- Дневная/ночная темы (дневная по умолчанию; переключатель в заголовке).
- Мобильный адаптивный макет с кнопками, удобными для сенсорного управления.
- Работает полностью в автономном режиме — никаких сетевых запросов в любое время.
- Устанавливается как PWA (Добавить на главный экран / Установить приложение) при хостинге по HTTPS.

## Начало работы

Просто откройте `index.html` в современном браузере. Без шага сборки, без установки, без сервера.

Если вы хотите хостить его, разместите статические файлы (`index.html`, `style.css`, `app.js`, `favicon.svg`, `manifest.webmanifest`, `service-worker.js`, единый файл `i18n.js`, содержащий все 28 словарей языков, и единый файл `contests.js`, содержащий все 68 конфигураций соревнований) на любом статическом хостинге (GitHub Pages, Netlify, собственный веб-сервер). Работает и через `file://` — регистрация service worker автоматически пропускается на протоколе `file:`, поэтому открытие `index.html` непосредственно с диска работает корректно.

При хостинге по HTTPS приложение становится устанавливаемым как PWA (меню *Установить приложение* / *Добавить на главный экран*) и работает в автономном режиме после первого посещения благодаря service worker с приоритетом кэша, предварительно кэширующему каждый статический файл (UI + все переводы).

Журнал по умолчанию создаётся автоматически при первом посещении, поэтому можно сразу начать вести записи.

## Журналы

- **Создать:** введите название в поле *Название журнала* и отправьте. Если оставить название пустым, по умолчанию устанавливается `Log YYYY-MM-DD HH:MM UTC`.
- **Переключить:** нажмите на любой журнал на боковой панели.
- **Переименовать:** нажмите *Переименовать* в заголовке журнала. Нажмите Enter для сохранения, Escape для отмены.
- **Удалить:** нажмите *Удалить журнал*. Будет запрошено подтверждение. Если удалить последний журнал, автоматически создастся новый.

## QSO-связи

- Заполните форму и нажмите **Записать QSO**.
- Форма организована в три блока:
  - **Данные станции** — *Позывной станции* (ваш передающий позывной, ADIF `STATION_CALLSIGN`), *Оператор* (позывной индивидуального оператора — отличается от *Позывного станции*, когда приглашённый оператор работает за микрофоном клубной станции; ADIF `OPERATOR`) и *Мой локатор* (ADIF `MY_GRIDSQUARE`). Они остаются неизменными между QSO в рамках одного сеанса — задайте их один раз, и они перенесутся.
  - **Режим работы** — *Режим распр.*, *Режим*, *Диапазон* и спутниковые поля *Спутник* / *Sat mode* / *Диапазон приёма*, когда режим распространения — *Спутник*. Диапазон, режим и режим распространения постоянны, как и Данные станции.
  - **Данные QSO** — поля каждой связи: *Позывной*, *Локатор* (локаторная ячейка Maidenhead другой станции), *Комментарий* (ADIF `COMMENT`), *RST отправлено*, *RST принято*. При редактировании существующей QSO в этом блоке также появляются *Дата (UTC)* и *Время (UTC)*. Эти поля очищаются после каждого *Записать QSO*.
- Все позывные (вызываемый, станция, оператор) автоматически переводятся в верхний регистр при вводе; оба поля локатора — аналогично.
- Дата и время предзаполняются значением *сейчас* по UTC при отправке; при редактировании можно ввести любое значение.
- RST отправлено / RST принято, если оставлены пустыми, по умолчанию **59** для голосовых режимов (SSB/FM/DIGITALVOICE) и **599** для CW и цифровых режимов (CW/FT8/FT4/RTTY/PSK31/JT65). Значение по умолчанию определяется родительским MODE, поэтому выбор конкретного подрежима, например *USB* или *FT4*, всё равно даёт правильное значение по умолчанию.
- Значок *Дубликат в этом журнале* появляется под полем позывного, если позывной уже есть в текущем журнале. Дубликаты *не блокируются*.
- **Режим распространения** — необязательный выпадающий список режимов распространения ADIF (SAT, RPT, EME, F2, Es, MS, LOS и т.д.). Оставьте пустым для обычных КВ-наземных QSO.
- **Спутниковые QSO** — выбор режима распространения *Спутник* открывает три спутниковых поля: **Спутник** (выпадающий список ~110 аппаратов, зарегистрированных AMSAT), **Sat mode** (буквенные обозначения AMSAT, сгруппированные как *современные* двухбуквенные коды восходящего/нисходящего канала вверху и *устаревшие* однобуквенные коды внизу) и **Диапазон приёма** (нисходящий диапазон). Спутник, Sat mode и Диапазон приёма обязательны — браузер откажет в отправке без них. Выбор **Sat mode** автоматически заполняет главный **Диапазон** восходящим каналом и **Диапазон приёма** нисходящим (например, режим J → 2m восходящий, 70cm нисходящий). Переключение *обратно* на спутник с другого режима распространения сбрасывает Sat mode, предлагая выбрать новый. Неспутниковые QSO никогда не несут спутниковых полей; переключение существующего QSO со спутника на другой режим распространения аккуратно их удаляет. **Локатор** и **Мой локатор** — общие поля (также полезные для VHF/UHF соревнований по локаторам) и остаются видимыми для каждого QSO.
- **Редактировать QSO** кнопкой *Изменить* в строке. Форма переключается в режим *Обновить QSO*, строка выделяется и появляется кнопка *Отмена*. Переключение журналов или удаление журнала автоматически отменяет редактирование.
- **Удалить QSO** кнопкой *Удалить* в строке (запрашивает подтверждение).

## Соревнования

Журнал может опционально быть **контестным журналом** — выберите соревнование из выпадающего списка *Соревнование* в форме создания журнала. Пустое поле = обычный журнал (по умолчанию, существующее поведение не меняется).

Контестные журналы получают:

- **Блок контестного обмена** в форме QSO, отображаемый динамически по схеме выбранного соревнования. Типы полей: `text`, `number` и `serial` (автоинкрементируемое, только для чтения). Поля с флагом *sticky* (ваша зона / район / дистрикт / мощность / возраст / …) заполняются предварительно из значения предыдущего QSO; поля отдельного QSO (их зона, их серийный, …) очищаются после каждого *Записать QSO*.
- **Значок соревнования** рядом с названием журнала в заголовке.
- **Обнаружение дубликатов** соблюдает `duplicateRule` соревнования (`per-band-mode`, `per-band`, `per-day` или `off`). Индикатор остаётся информационным — никогда не блокирует отправку.
- **Индикатор предупреждения**, когда текущее UTC выпадает за пределы объявленных дат соревнования (12 лет предзагружено, 2026–2037) или когда выбранный диапазон / режим не входит в разрешённый набор соревнования. Никогда не блокирует.
- **Панель информации для подачи** в заголовке журнала: встроенная форма для полей заголовка Cabrillo, объявленных соревнованием (категория, мощность, имя, клуб, адрес, комментарий, …). Значения сохраняются в журнале, а не в отдельном QSO.
- **Кнопка Экспорт .cbr** в заголовке журнала, рядом с *Экспорт .adi*. Создаёт файл Cabrillo v3: `CALLSIGN` / `GRID-LOCATOR` / `OPERATORS` предварительно заполнены из данных станции первого QSO, остальное — из панели информации для подачи, затем по одной строке `QSO:` на каждую связь в хронологическом порядке, используя столбцы `sentTemplate` / `rcvdTemplate` соревнования.
- **Повторный импорт Cabrillo** через стандартную кнопку *Импортировать файл журнала* — файл `.cbr`, ранее экспортированный приложением (или любым другим логгером, выдающим стандартный Cabrillo v3), возвращается в новый контестный журнал правильного типа. Заголовок `CONTEST:` сопоставляется со встроенным каталогом; когда несколько конфигураций имеют одинаковую метку (например, `ARRL-10` соответствует и `arrl-10m-dx`, и `arrl-10m-w`), приложение разрешает неоднозначность по букве режима строки QSO и количеству столбцов, а затем предпочитает вариант `-dx`. Поля заголовка (категория, имя, клуб, комментарий и т. д.) восстанавливают панель информации для подачи; значения обмена QSO восстанавливают `q.contestExchange` согласно шаблону соревнования.

### Каталог встроенных соревнований (68 конфигураций)

Сгруппировано по семействам:

- **Семейство CQ** (9): CQ WW SSB/CW/RTTY, CQ WPX SSB/CW/RTTY, CQ 160 CW/SSB, CQ-M International.
- **Семейство ARRL** (9): ARRL DX SSB/CW (со стороны DX), ARRL Field Day, ARRL 10m/160m/RTTY Roundup (каждое поставляется в *двух* вариантах — DX и W/VE).
- **IARU** (2): IARU HF Championship, IARU R1 Field Day.
- **WAE и другие европейские** (8): WAE DX SSB/CW, EU HF Championship, LZ DX, Baltic Contest, NRAU-Baltic SSB/CW, SP DX.
- **Центральноевропейские / восточноевропейские асимметричные — оба варианта** (14): OK/OM DX CW+SSB, HA DX, YO DX HF, Ukrainian DX, REF Contest CW+SSB.
- **Российские клубные / RadioSport** (12): Russian DX (обе стороны), Russian WW RTTY, Russian WW MultiMode, Yuri Gagarin International, Кубок России CW+SSB, RRTC, Asiatic Russia Championship, Мемориал UA1DZ, RDAC, RAEM.
- **Беларусь + Италия + Хорватия + Испания + Ukrainian RTTY** (12): Belarus BFRR CW+SSB (обе стороны), ARI DX (обе стороны), Croatian 9A CW (обе стороны), Spanish CNCW (обе стороны), Ukrainian RTTY (обе стороны).
- **Глобальные** (2): All Asian DX CW+SSB.

Асимметричные соревнования (где хозяева и DX стороны отправляют разный обмен) поставляются в **двух конфигурациях** — одна для перспективы страны-хозяина (фиксированный региональный код) и одна для перспективы DX (фиксированный серийный номер). Поле принимаемой стороны — единое свободное текстовое поле, чтобы оператор мог ввести любой формат в зависимости от контакта.

Каждая конфигурация содержит:

- Значения контестного обмена, повторно выводимые при экспорте ADIF через поля пространства имён `APP_LQ_*`; штамп заголовка `APP_LQ_CONTEST_ID` позволяет последующему повторному импорту восстановить журнал как то же соревнование со всеми полями обмена в целости.
- 12 лет дат соревнований (2026–2037), чтобы значок *вне окна соревнования* оставался полезным на десятилетие без переиздания.
- Шаблон Cabrillo, сопоставляющий каждое поле обмена правильному столбцу строки `QSO:`.

Добавление нового соревнования = вставьте новый IIFE-блок в [`contests.js`](contests.js) в алфавитной позиции (каждое существующее соревнование выделено заголовочным комментарием `// ==== <id> ====`, поэтому легко найти, куда вставить). Изменения в `index.html`, `service-worker.js` или `app.js` не требуются — рендерер, обработчик отправки, детектор дубликатов, круговой обмен ADIF и генератор Cabrillo принимают каждую конфигурацию как чистые данные.

## Импорт и экспорт

- **Импорт** любого файла журнала — нажмите *Импортировать файл журнала* под формой создания журнала и выберите файл `.adi` / `.adif` (ADIF) или `.cbr` / `.cab` (Cabrillo v3). Формат определяется автоматически по первой строке файла (`<...>` → ADIF, `START-OF-LOG:` → Cabrillo, `[REG1TEST;1]` → сообщение «EDI пока не поддерживается»). Всегда создаётся новый журнал — импорт никогда не сливается с существующим. ADIF-импорт создаёт обычный журнал, если только заголовок не содержит `APP_LQ_CONTEST_ID`, записанный нашим собственным экспортом соревнования (в этом случае журнал восстанавливается как контестный этого соревнования). Cabrillo-импорт всегда создаёт контестный журнал — см. раздел *Соревнования* о том, как метка `CONTEST:` сопоставляется со встроенным каталогом.
- **Экспорт ADIF**: нажмите *Экспортировать .adi* в заголовке журнала. Загружается файл, соответствующий **ADIF 3.1.7**. Заголовок декларирует `ADIF_VER 3.1.7`, `PROGRAMID local-qso`, `PROGRAMVERSION` и `CREATED_TIMESTAMP` (UTC). Выводимые поля QSO (когда не пусты): `CALL`, `QSO_DATE`, `TIME_ON`, `BAND`, `MODE`, `SUBMODE`, `PROP_MODE`, `GRIDSQUARE`, `BAND_RX`, `SAT_MODE`, `SAT_NAME`, `RST_SENT`, `RST_RCVD`, `COMMENT`, `STATION_CALLSIGN`, `OPERATOR`, `MY_GRIDSQUARE` — затем каждое дополнительное поле ADIF, сохранённое при импорте (см. ниже).
- **Экспорт Cabrillo** описан выше в разделе *Соревнования* — он доступен только для контестных журналов (кнопка *Экспорт .cbr* появляется в заголовке журнала, когда у журнала задано соревнование).
- **Безпотерьный двунаправленный обмен**: при ADIF-импорте любое поле, которое приложение не моделирует в UI (например, `NAME`, `FREQ`, `TX_PWR`, `DXCC`, `QSL_SENT`/`QSL_RCVD`, `POTA_REF`, поля `APP_*`), сохраняется в QSO и при следующем ADIF-экспорте воспроизводится дословно. Таким образом, экспорт файла, который сам был импортирован, сохраняет всё.
- Длина поля в ADIF трактуется как количество байт UTF-8, как того требует спецификация, поэтому многобайтный текст (например, позывные с диакритикой в `COMMENT`) разбирается корректно.

## Конфиденциальность и данные

- Все данные хранятся в `localStorage` браузера под ключом `local-qso:v1`.
- Ничего никуда не передаётся. Нет бэкенда, нет API-запросов, нет телеметрии, нет аналитики.
- Очистка данных сайта в браузере, использование приватного/инкогнито-режима или другого браузера/устройства означает новый пустой журнал — используйте *Экспортировать .adi* для резервного копирования.

## Технические примечания

- Одностраничное приложение, ванильный HTML + CSS + JavaScript. Без фреймворков, без шага сборки, без зависимостей.
- Исходные файлы:
  - `index.html` — разметка и мета-теги.
  - `style.css` — темы и макет (переменные дня/ночи, медиазапросы для мобильных).
  - `app.js` — состояние, хранение, рендеринг, парсер/сериализатор ADIF, поиск префикса позывного → страна.
  - `favicon.svg` — встроенный SVG-фавикон.
  - `manifest.webmanifest` — Web App Manifest (название, цвет темы, область, иконка), чтобы приложение было устанавливаемым как PWA на мобильном и десктопе.
  - `service-worker.js` — service worker с приоритетом кэша, предварительно кэширующий каждый статический файл при установке, вытесняющий старые кэши при активации и поддерживающий приложение полностью автономным после первого посещения. Регистрация автоматически пропускается на протоколе `file://`, поэтому открытие `index.html` непосредственно с диска остаётся корректным.
  - `i18n.js` — единый вручную поддерживаемый файл со всеми 28 словарями языков. Каждый язык — самодостаточный IIFE, присваивающий `window.I18N[<lang>]` плоское отображение ключ→строка. Блоки разделены заголовочными комментариями `// ==== <lang> ====` — grep по одному переносит к нужному языку. Собран в один файл вместо 28 отдельных, потому что файлы переводов сильно повторяются (одни и те же имена ключей, синтаксис плейсхолдеров), и gzip сжимает весь набор гораздо лучше, чем 28 отдельных потоков — экономит ~23 КБ на передаче при первой загрузке и убирает 27 HTTP-запросов. `t()` и `applyLanguage()` в `app.js` обрабатывают поиски (с резервным английским) и обходят DOM, обновляя каждый элемент `[data-i18n*]`.
  - `contests.js` — единый вручную поддерживаемый файл со всеми 68 конфигурациями соревнований. Каждое соревнование — самодостаточный IIFE, присваивающий `window.CONTESTS[<id>]` объект конфигурации, соответствующий схеме (`{name, shortName, windows[], bands[], modes[], exchange[], duplicateRule, cabrillo}`). Блоки разделены заголовочными комментариями `// ==== <id> ====` — grep по одному переносит к нужному соревнованию. Собран в один файл вместо 68 отдельных, потому что конфигурации соревнований сильно повторяются (одна и та же схема, префикс `APP_LQ_*`, названия полей заголовка Cabrillo), и gzip сжимает весь набор гораздо лучше, чем 68 отдельных потоков — экономит ~42 КБ на передаче при первой загрузке и убирает 67 HTTP-запросов. Загружается одним тегом `<script>` в `index.html` перед `app.js`, чтобы реестр был заполнен при построении выпадающего списка соревнований.
- Проверено на актуальных Chromium, Firefox и Safari (десктоп + iOS).
