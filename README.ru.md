Аппаратный журнал QSO для радиолюбителей, уважающий вашу конфиденциальность и работающий целиком в браузере. Без учётной записи, без сервера, без отслеживания, без аналитики — ваши журналы хранятся только в `localStorage` браузера и никогда не покидают ваше устройство.

Автор: [YL3IM](https://www.qrz.com/db/YL3IM). Сайт проекта: [qso.lv](https://qso.lv).

## Возможности

- Несколько журналов; у каждого свой список QSO-связей.
- Действия с журналом: создание, переименование, удаление, импорт из ADIF, экспорт в ADIF (`.adi`).
- Форма QSO разбита на три блока: **Данные станции** (позывной станции, позывной оператора, собственная локаторная ячейка) остаётся неизменным между QSO; **Режим работы** (режим распространения, спутник, режим, спутниковый режим, диапазон, диапазон приёма) со спутниковыми полями, появляющимися только при режиме распространения *Спутник*; и **Данные QSO** (позывной вызываемой станции, локатор вызываемой, дата/время UTC при редактировании, комментарий, RST отправлено, RST принято).
- Полная таксономия ADIF `MODE` → `SUBMODE` в выпадающем списке режимов — выберите родительский режим (`SSB`, `MFSK`, …) или перейдите сразу к конкретному подрежиму (`USB`, `FT4`, …); приложение хранит оба поля согласно ADIF, а таблица отображает конкретный подрежим, если он есть.
- Полное перечисление режимов распространения ADIF (SAT, RPT, EME, ES, MS, Aurora и т.д.) в виде выпадающего списка.
- Полный каталог спутников AMSAT (~110 аппаратов) и двухуровневый выпадающий список **Sat mode**: предпочтительные двухбуквенные коды восходящего/нисходящего канала вверху (LU, LV, SX, UU, UV, VA, VU, VV) и устаревшие однобуквенные обозначения (A/B/J/K/L/R/S/T/U/V/W/X) сгруппированы как *устаревшие* внизу. Выбор спутникового режима автоматически устанавливает восходящий `BAND` и нисходящий `RX band`.
- Редактирование и удаление любой QSO-связи (с подтверждением при удалении).
- Разумные значения по умолчанию: сегодняшняя дата/время UTC заполняются заранее, RST по умолчанию зависит от режима (59 для голосовых, 599 для CW/цифровых), постоянные Данные станции + диапазон + режим + режим распространения между последовательными QSO (только поля каждой связи — позывной, локатор, комментарий, RST — очищаются после каждого *Записать QSO*).
- Живой индикатор дублирующего позывного (информационный — дубликаты разрешены).
- Столбец флага страны, определяемый по префиксу позывного (охватывает ≥99 % распространённых любительских префиксов, включая переносные позывные типа `9A/M0NCG`).
- Отображение даты в соответствии с локалью в таблице QSO; хранение и вывод ADIF остаются в формате ISO.
- Интерфейс на **28 языках** (английский плюс 22 на латинице, 5 на кириллице и греческий); селектор с флаговыми эмодзи в заголовке.
- Дневная/ночная темы (дневная по умолчанию; переключатель в заголовке).
- Мобильный адаптивный макет с кнопками, удобными для сенсорного управления.
- Работает полностью в автономном режиме — никаких сетевых запросов в любое время.
- Устанавливается как PWA (Добавить на главный экран / Установить приложение) при хостинге по HTTPS.

## Начало работы

Просто откройте `index.html` в современном браузере. Без шага сборки, без установки, без сервера.

Если вы хотите хостить его, разместите статические файлы (`index.html`, `style.css`, `app.js`, `favicon.svg`, `manifest.webmanifest`, `service-worker.js` и каталог `i18n/` с 28 файлами переводов) на любом статическом хостинге (GitHub Pages, Netlify, собственный веб-сервер). Работает и через `file://` — регистрация service worker автоматически пропускается на протоколе `file:`, поэтому открытие `index.html` непосредственно с диска работает корректно.

При хостинге по HTTPS приложение становится устанавливаемым как PWA (меню *Установить приложение* / *Добавить на главный экран*) и работает в автономном режиме после первого посещения благодаря service worker с приоритетом кэша, предварительно кэширующему каждый статический файл (UI + все переводы).

Журнал по умолчанию создаётся автоматически при первом посещении, поэтому можно сразу начать вести записи.

## Журналы

- **Создать:** введите название в поле *Название журнала* и отправьте. Если оставить название пустым, по умолчанию устанавливается `Log YYYY-MM-DD HH:MM UTC`.
- **Переключить:** нажмите на любой журнал на боковой панели.
- **Переименовать:** нажмите *Переименовать* в заголовке журнала. Нажмите Enter для сохранения, Escape для отмены.
- **Удалить:** нажмите *Удалить журнал*. Будет запрошено подтверждение. Если удалить последний журнал, автоматически создастся новый.

## QSO-связи

- Заполните форму и нажмите **Записать QSO**.
- Форма организована в три блока:
  - **Данные станции** — *Позывной станции* (ваш передающий позывной, ADIF `STATION_CALLSIGN`), *Оператор* (позывной индивидуального оператора — отличается от *Позывного станции*, когда приглашённый оператор работает за микрофоном клубной станции; ADIF `OPERATOR`) и *Мой локатор* (ADIF `MY_GRIDSQUARE`). Они остаются неизменными между QSO в рамках одного сеанса — задайте их один раз, и они перенесутся.
  - **Режим работы** — *Режим распр.*, *Режим*, *Диапазон* и спутниковые поля *Спутник* / *Sat mode* / *Диапазон приёма*, когда режим распространения — *Спутник*. Диапазон, режим и режим распространения постоянны, как и Данные станции.
  - **Данные QSO** — поля каждой связи: *Позывной*, *Локатор* (локаторная ячейка Maidenhead другой станции), *Комментарий* (ADIF `COMMENT`), *RST отправлено*, *RST принято*. При редактировании существующей QSO в этом блоке также появляются *Дата (UTC)* и *Время (UTC)*. Эти поля очищаются после каждого *Записать QSO*.
- Все позывные (вызываемый, станция, оператор) автоматически переводятся в верхний регистр при вводе; оба поля локатора — аналогично.
- Дата и время предзаполняются значением *сейчас* по UTC при отправке; при редактировании можно ввести любое значение.
- RST отправлено / RST принято, если оставлены пустыми, по умолчанию **59** для голосовых режимов (SSB/FM/DIGITALVOICE) и **599** для CW и цифровых режимов (CW/FT8/FT4/RTTY/PSK31/JT65). Значение по умолчанию определяется родительским MODE, поэтому выбор конкретного подрежима, например *USB* или *FT4*, всё равно даёт правильное значение по умолчанию.
- Значок *Дубликат в этом журнале* появляется под полем позывного, если позывной уже есть в текущем журнале. Дубликаты *не блокируются*.
- **Режим распространения** — необязательный выпадающий список режимов распространения ADIF (SAT, RPT, EME, F2, Es, MS, LOS и т.д.). Оставьте пустым для обычных КВ-наземных QSO.
- **Спутниковые QSO** — выбор режима распространения *Спутник* открывает три спутниковых поля: **Спутник** (выпадающий список ~110 аппаратов, зарегистрированных AMSAT), **Sat mode** (буквенные обозначения AMSAT, сгруппированные как *современные* двухбуквенные коды восходящего/нисходящего канала вверху и *устаревшие* однобуквенные коды внизу) и **Диапазон приёма** (нисходящий диапазон). Спутник, Sat mode и Диапазон приёма обязательны — браузер откажет в отправке без них. Выбор **Sat mode** автоматически заполняет главный **Диапазон** восходящим каналом и **Диапазон приёма** нисходящим (например, режим J → 2m восходящий, 70cm нисходящий). Переключение *обратно* на спутник с другого режима распространения сбрасывает Sat mode, предлагая выбрать новый. Неспутниковые QSO никогда не несут спутниковых полей; переключение существующего QSO со спутника на другой режим распространения аккуратно их удаляет. **Локатор** и **Мой локатор** — общие поля (также полезные для VHF/UHF соревнований по локаторам) и остаются видимыми для каждого QSO.
- **Редактировать QSO** кнопкой *Изменить* в строке. Форма переключается в режим *Обновить QSO*, строка выделяется и появляется кнопка *Отмена*. Переключение журналов или удаление журнала автоматически отменяет редактирование.
- **Удалить QSO** кнопкой *Удалить* в строке (запрашивает подтверждение).

## Импорт и экспорт ADIF

- **Экспорт**: нажмите *Экспортировать .adi* в заголовке журнала. Загружается файл, соответствующий **ADIF 3.1.7**. Заголовок декларирует `ADIF_VER 3.1.7`, `PROGRAMID local-qso`, `PROGRAMVERSION` и `CREATED_TIMESTAMP` (UTC). Выводимые поля QSO (когда не пусты): `CALL`, `QSO_DATE`, `TIME_ON`, `BAND`, `MODE`, `SUBMODE`, `PROP_MODE`, `GRIDSQUARE`, `BAND_RX`, `SAT_MODE`, `SAT_NAME`, `RST_SENT`, `RST_RCVD`, `COMMENT`, `STATION_CALLSIGN`, `OPERATOR`, `MY_GRIDSQUARE` — затем каждое дополнительное поле ADIF, сохранённое при импорте (см. ниже).
- **Импорт**: нажмите *Импортировать файл .adi* под формой создания журнала и выберите файл `.adi` / `.adif`. Из него создаётся новый журнал с именем `Imported YYYY-MM-DD HH:MM UTC`. Импорт никогда не сливается с существующим журналом.
- **Безпотерьный двунаправленный обмен**: при импорте любое поле ADIF, которое приложение не моделирует в UI (например, `NAME`, `FREQ`, `TX_PWR`, `DXCC`, `QSL_SENT`/`QSL_RCVD`, `POTA_REF`, поля `APP_*`), сохраняется в QSO и при следующем экспорте воспроизводится дословно. Таким образом, экспорт файла, который сам был импортирован, сохраняет всё.
- Длина поля трактуется как количество байт UTF-8, как того требует спецификация, поэтому многобайтный текст (например, позывные с диакритикой в `COMMENT`) разбирается корректно.

## Конфиденциальность и данные

- Все данные хранятся в `localStorage` браузера под ключом `local-qso:v1`.
- Ничего никуда не передаётся. Нет бэкенда, нет API-запросов, нет телеметрии, нет аналитики.
- Очистка данных сайта в браузере, использование приватного/инкогнито-режима или другого браузера/устройства означает новый пустой журнал — используйте *Экспортировать .adi* для резервного копирования.

## Темы

Переключатель темы в заголовке переключает между дневной (по умолчанию) и ночной. Настройка сохраняется вместе с журналами и учитывается при следующем посещении. Нативные выбиратели даты/времени следуют теме через `color-scheme`.

## Технические примечания

- Одностраничное приложение, ванильный HTML + CSS + JavaScript. Без фреймворков, без шага сборки, без зависимостей.
- Исходные файлы:
  - `index.html` — разметка и мета-теги.
  - `style.css` — темы и макет (переменные дня/ночи, медиазапросы для мобильных).
  - `app.js` — состояние, хранение, рендеринг, парсер/сериализатор ADIF, поиск префикса позывного → страна.
  - `favicon.svg` — встроенный SVG-фавикон.
  - `manifest.webmanifest` — Web App Manifest (название, цвет темы, область, иконка), чтобы приложение было устанавливаемым как PWA на мобильном и десктопе.
  - `service-worker.js` — service worker с приоритетом кэша, предварительно кэширующий каждый статический файл при установке, вытесняющий старые кэши при активации и поддерживающий приложение полностью автономным после первого посещения. Регистрация автоматически пропускается на протоколе `file://`, поэтому открытие `index.html` непосредственно с диска остаётся корректным.
  - `i18n/<lang>.js` — один файл перевода для каждого поддерживаемого языка (28 всего). Каждый — небольшой IIFE, присваивающий `window.I18N[<lang>]` плоское отображение ключ→строка. `t()` и `applyLanguage()` в `app.js` обрабатывают поиски (с резервным английским) и обходят DOM, обновляя каждый элемент `[data-i18n*]`.
- Проверено на актуальных Chromium, Firefox и Safari (десктоп + iOS).

Флаги стран опираются на последовательности региональных индикаторов Unicode. Они корректно отображаются на macOS, iOS, Linux (при наличии эмодзи-шрифта с поддержкой флагов) и Android. Windows не включает системный шрифт флагов, поэтому флаговые эмодзи могут отображаться там как пары букв.
