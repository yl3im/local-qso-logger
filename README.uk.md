Апаратний журнал QSO для радіоаматорів, що поважає конфіденційність і повністю працює у браузері. Без облікового запису, без сервера, без відстеження, без аналітики — ваші журнали зберігаються лише в `localStorage` браузера і ніколи не залишають ваш пристрій.

Автор: [YL3IM](https://www.qrz.com/db/YL3IM). Вебсайт проєкту: [qso.lv](https://qso.lv).

## Можливості

- Декілька журналів; кожен зі своїм списком QSO-зв'язків.
- **Журнали змагань** необов'язкові — виберіть із каталогу 68 вбудованих змагань під час створення журналу. Форма QSO отримує специфічний для змагання блок *Обмін змагання*, виявлення дублікатів враховує правило змагання, а *Експортувати .cbr* створює файл подання Cabrillo v3 поряд зі звичайним експортом ADIF.
- Дії з журналом: створення, перейменування, видалення, імпорт файлу журналу (ADIF або Cabrillo — формат визначається автоматично), експорт у ADIF (`.adi`), плюс *Експортувати .cbr* (Cabrillo v3) для журналів змагань. Повторний імпорт файлу `.cbr`, раніше експортованого застосунком, відновлює його як той самий журнал змагання.
- Форма QSO згрупована у три блоки: **Дані станції** (позивний станції, позивний оператора, власна комірка) залишається незмінним між QSO-зв'язками; **Режим роботи** (режим поширення, супутник, режим, супутниковий режим, діапазон, діапазон прийому) з полями для супутника, що з'являються лише при режимі поширення *Супутник*; і **Дані QSO** (позивний викликуваної станції, комірка викликуваної, дата/час UTC під час редагування, коментар, RST надіслано, RST отримано).
- Повна таксономія ADIF `MODE` → `SUBMODE` у випадному списку режимів — виберіть батьківський режим (`SSB`, `MFSK`, …) або перейдіть безпосередньо до конкретного підрежиму (`USB`, `FT4`, …); застосунок зберігає обидва поля відповідно до ADIF, а таблиця показує конкретний підрежим, якщо він є.
- Повне перерахування режимів поширення ADIF (SAT, RPT, EME, ES, MS, Aurora тощо) у вигляді випадного списку.
- Повний каталог супутників AMSAT (~110 апаратів) і дворівневий випадний список **Sat mode**: бажані двобуквені коди висхідного/нисхідного каналу вгорі (LU, LV, SX, UU, UV, VA, VU, VV) і застарілі однобуквені позначення (A/B/J/K/L/R/S/T/U/V/W/X) згруповані як *застарілі* внизу. Вибір супутникового режиму автоматично встановлює висхідний `BAND` і нисхідний `RX band`.
- Редагування та видалення будь-якого QSO-зв'язку (з підтвердженням при видаленні).
- Розумні значення за замовчуванням: сьогоднішня дата/час UTC заповнені заздалегідь, RST за замовчуванням залежить від режиму (59 для голосових, 599 для CW/цифрових), постійні Дані станції + діапазон + режим + режим поширення між послідовними QSO-зв'язками (лише поля кожного зв'язку — позивний, комірка, коментар, RST — очищаються після кожного *Занести QSO*).
- Живий індикатор дублікату позивного (інформаційний — дублікати дозволені).
- Стовпець прапора країни, визначений за префіксом позивного (охоплює ≥99 % поширених аматорських префіксів, включаючи переносні позивні на кшталт `9A/M0NCG`).
- Однодотикове автоматичне визначення поля **Моя комірка**: кнопка 🌐 поруч із полем запитує в браузера ваші поточні координати та заповнює 6-символьну комірку Maidenhead (використовує Geolocation API браузера — потребує дозволу користувача).
- Відображення дати відповідно до локалі в таблиці QSO; зберігання та виведення ADIF залишаються у форматі ISO.
- Інтерфейс на **28 мовах** (англійська плюс 22 латиницею, 5 кирилицею і грецька); селектор з прапоровими емодзі в заголовку.
- Денна/нічна теми (денна за замовчуванням; перемикач у заголовку).
- Мобільний адаптивний макет з кнопками, зручними для дотику.
- Працює повністю в автономному режимі — жодних мережевих запитів будь-коли.
- Встановлюється як PWA (Додати на головний екран / Встановити застосунок) при хостингу по HTTPS.

## Початок роботи

Просто відкрийте `index.html` у сучасному браузері. Без кроку збірки, без встановлення, без сервера.

Якщо ви хочете розгорнути його, розмістіть статичні файли (`index.html`, `style.css`, `app.js`, `favicon.svg`, `manifest.webmanifest`, `service-worker.js`, єдиний пакет `i18n.js`, що несе всі 28 мовних словників, і єдиний пакет `contests.js`, що несе всі 68 конфігурацій змагань) на будь-якому статичному хостингу (GitHub Pages, Netlify, власний вебсервер). Також працює через `file://` — реєстрація service worker автоматично пропускається на протоколі `file:`, тому відкриття `index.html` безпосередньо з диска працює коректно.

При хостингу по HTTPS застосунок стає встановлюваним як PWA (меню *Встановити застосунок* / *Додати на головний екран*) і працює в автономному режимі після першого відвідування завдяки service worker з пріоритетом кешу, який попередньо кешує кожен статичний файл (UI + всі переклади).

Журнал за замовчуванням створюється автоматично при першому відвідуванні, тому можна одразу почати вести записи.

## Встановлення як PWA на мобільному

Коли застосунок хоститься по HTTPS (наприклад, GitHub Pages), його можна встановити на головний екран телефону, де він працює у повноекранному режимі без елементів браузера. Після першого запуску service worker кешує все, тому наступні запуски працюють повністю в автономному режимі.

### iOS (лише Safari)

В iOS лише Safari може встановлювати PWA — браузери сторонніх розробників не можуть.

## Журнали

- **Створити:** введіть назву в *Назва журналу* і надішліть. Якщо залишити назву порожньою, за замовчуванням встановлюється `Log YYYY-MM-DD HH:MM UTC`.
- **Переключити:** натисніть на будь-який журнал на бічній панелі.
- **Перейменувати:** натисніть *Перейменувати* в заголовку журналу. Натисніть Enter для збереження, Escape для скасування.
- **Видалити:** натисніть *Видалити журнал*. Буде запрошено підтвердження. Якщо видалити останній журнал, автоматично створюється новий.

## QSO-зв'язки

- Заповніть форму і натисніть **Занести QSO**.
- Форма організована у три блоки:
  - **Дані станції** — *Позивний станції* (ваш передавальний позивний, ADIF `STATION_CALLSIGN`), *Оператор* (позивний індивідуального оператора — відрізняється від *Позивного станції*, коли запрошений оператор працює за мікрофоном клубної станції; ADIF `OPERATOR`) і *Моя комірка* (ADIF `MY_GRIDSQUARE`) з кнопкою 🌐, яка заповнює комірку з поточного розташування вашого браузера (Geolocation API — браузер попросить дозвіл вперше). Вони залишаються незмінними між QSO-зв'язками в одному сеансі — задайте їх один раз і вони переносяться.
  - **Режим роботи** — *Режим пошир.*, *Режим*, *Діапазон* і поля для супутника *Супутник* / *Sat mode* / *Діапазон прийому*, коли режим поширення — *Супутник*. Діапазон, режим і режим поширення постійні, як і Дані станції.
  - **Дані QSO** — поля кожного зв'язку: *Позивний*, *Комірка* (комірка Maidenhead іншої станції), *Коментар* (ADIF `COMMENT`), *RST надіслано*, *RST отримано*. При редагуванні наявного QSO-зв'язку у цьому блоці також з'являються *Дата (UTC)* і *Час (UTC)*. Ці поля очищаються після кожного *Занести QSO*.
- Всі позивні (викликуваний, станція, оператор) автоматично перетворюються на великі літери при введенні; обидва поля комірки — аналогічно.
- Дата і час заповнюються *зараз* UTC при надсиланні; при редагуванні можна ввести будь-яке значення.
- RST надіслано / RST отримано, якщо залишені порожніми, за замовчуванням **59** для голосових режимів (SSB/FM/DIGITALVOICE) і **599** для CW та цифрових режимів (CW/FT8/FT4/RTTY/PSK31/JT65). Значення за замовчуванням визначається батьківським MODE, тому вибір конкретного підрежиму на кшталт *USB* або *FT4* все одно дає правильне значення за замовчуванням.
- Значок *Дублікат у цьому журналі* з'являється під полем позивного, якщо позивний вже є в поточному журналі. Дублікати *не блокуються*.
- **Режим поширення** — необов'язковий випадний список режимів поширення ADIF (SAT, RPT, EME, F2, Es, MS, LOS тощо). Залиште порожнім для звичайних КХ-наземних QSO-зв'язків.
- **Супутникові QSO-зв'язки** — вибір режиму поширення *Супутник* відкриває три поля для супутника: **Супутник** (випадний список ~110 апаратів, зареєстрованих AMSAT), **Sat mode** (буквені позначення AMSAT, згруповані як *сучасні* двобуквені коди висхідного/нисхідного каналу вгорі і *застарілі* однобуквені коди внизу) і **Діапазон прийому** (нисхідний діапазон). Супутник, Sat mode і Діапазон прийому обов'язкові — браузер відмовить у надсиланні без них. Вибір **Sat mode** автоматично заповнює головний **Діапазон** висхідним каналом і **Діапазон прийому** нисхідним (наприклад, режим J → 2m висхідний, 70cm нисхідний). Переключення *назад* на супутник з іншого режиму поширення скидає Sat mode, тому вас попросять вибрати новий. Несупутникові QSO-зв'язки ніколи не несуть супутникових полів; переключення наявного QSO-зв'язку із супутника на інший режим поширення акуратно їх видаляє. **Комірка** і **Моя комірка** — загальні поля (також корисні для VHF/UHF змагань за комірками) і залишаються видимими для кожного QSO.
- **Редагувати QSO-зв'язок** кнопкою *Редагувати* в рядку. Форма переключається в режим *Оновити QSO*, рядок виділяється і з'являється кнопка *Скасувати*. Переключення журналів або видалення журналу автоматично скасовує редагування.
- **Видалити QSO-зв'язок** кнопкою *Видалити* в рядку (запитує підтвердження).

## Змагання

Журнал може додатково бути **журналом змагання** — виберіть змагання зі спадного списку *Змагання* у формі створення журналу. Порожній список = звичайний журнал (за замовчуванням, наявна поведінка не змінюється).

Журнали змагань отримують:

- **Блок обміну змагання** у формі QSO, який динамічно відображається за схемою обраного змагання. Типи полів — `text`, `number` і `serial` (автоматично зростає, лише для читання). Поля, позначені як *sticky* (ваша власна зона / округ / район / потужність / вік / …), заповнюються заздалегідь зі значення попереднього QSO-зв'язку; поля кожного QSO (їхня зона, їхній серійний номер, …) очищаються після кожного *Занести QSO*.
- **Значок змагання** біля назви журналу в заголовку деталей.
- **Виявлення дублікатів** враховує `duplicateRule` змагання (`per-band-mode`, `per-band`, `per-day` або `off`). Значок залишається лише інформаційним — ніколи не блокує подання.
- **Значок попередження**, коли поточний UTC виходить за межі будь-якого з задекларованих змаганням вікон дат (12 років попередньо завантажені, 2026–2037), або коли обраний діапазон / режим не входить до дозволеного набору змагання. Ніколи не блокує.
- **Панель інформації про подання** у заголовку деталей: вбудована форма для полів заголовка Cabrillo, які декларує змагання (категорія, потужність, ім'я, клуб, адреса, soapbox, …). Значення зберігаються на журналі, не для кожного QSO.
- **Кнопка Експортувати .cbr** у заголовку деталей, поряд з *Експортувати .adi*. Створює файл Cabrillo v3: `CALLSIGN` / `GRID-LOCATOR` / `OPERATORS` заповнені заздалегідь з даних станції першого QSO-зв'язку, решта з панелі інформації про подання, потім один рядок `QSO:` на контакт у хронологічному порядку, використовуючи колонки `sentTemplate` / `rcvdTemplate` змагання.
- **Повторний імпорт Cabrillo** через стандартну кнопку *Імпортувати файл журналу* — файл `.cbr`, раніше експортований застосунком (або будь-яким іншим журналом, що створює стандартний Cabrillo v3), повертається у новий журнал змагання правильного типу. Заголовок `CONTEST:` порівнюється з вбудованим каталогом; коли кілька конфігурацій мають спільну мітку (наприклад, `ARRL-10` відповідає і `arrl-10m-dx`, і `arrl-10m-w`), застосунок розв'язує неоднозначність, порівнюючи літеру режиму рядка QSO і кількість колонок із шаблоном кожного кандидата, потім надає перевагу варіанту `-dx`. Поля заголовка (категорія, ім'я, клуб, soapbox, …) відновлюють панель інформації про подання; значення обміну QSO відновлюють `q.contestExchange` за шаблоном змагання.

### Вбудований каталог змагань (68 конфігурацій)

Згруповано за родинами:

- **Родина CQ** (9): CQ WW SSB/CW/RTTY, CQ WPX SSB/CW/RTTY, CQ 160 CW/SSB, CQ-M International.
- **Родина ARRL** (9): ARRL DX SSB/CW (сторона DX), ARRL Field Day, ARRL 10m/160m/RTTY Roundup (кожне постачається з *обох* перспектив — DX і W/VE).
- **IARU** (2): IARU HF Championship, IARU R1 Field Day.

- **Білорусь + Італія + Хорватія + Іспанія + український RTTY** (12): Belarus BFRR CW+SSB (обидві сторони), ARI DX (обидві сторони), Croatian 9A CW (обидві сторони), Spanish CNCW (обидві сторони), Ukrainian RTTY (обидві сторони).
- **Глобальні** (2): All Asian DX CW+SSB.

Асиметричні змагання (де країна-господар і сторона DX надсилають різний обмін) постачаються з **двома конфігураціями** — однією для перспективи країни-господаря (закріплений регіональний код) і однією для перспективи DX (закріплений серійний номер). Поле отриманої сторони — єдине поле вільного тексту, щоб оператор міг вводити будь-який формат залежно від контакту.

Кожна конфігурація містить:

- Значення обміну змагання повторно передаються при експорті ADIF через поля простору імен `APP_LQ_*`; штамп заголовка `APP_LQ_CONTEST_ID` дозволяє наступному повторному імпорту відновити журнал як те саме змагання з усіма недоторканими полями.
- 12 років вікон дат (2026–2037), тому значок *поза вікном змагання* залишається корисним десятиліття без нового випуску.
- Шаблон Cabrillo, що зіставляє кожне поле обміну з правильним стовпцем рядка `QSO:`.

Додавання нового змагання = вставте новий блок IIFE у [`contests.js`](contests.js) на алфавітну позицію (кожне наявне змагання відокремлюється коментарем заголовка `// ==== <id> ====`, тому легко знайти, куди вставити). Не потрібні жодні зміни в `index.html`, жодні зміни в `service-worker.js`, жодні зміни в `app.js` — рендерер, обробник подання, детектор дублікатів, ADIF циклічний обмін і передавач Cabrillo сприймають кожну конфігурацію як чисті дані.

## Імпорт та експорт

- **Імпортуйте** будь-який файл журналу — натисніть *Імпортувати файл журналу* під формою створення журналу і виберіть файл `.adi` / `.adif` (ADIF) або `.cbr` / `.cab` (Cabrillo v3). Формат визначається автоматично за першим рядком файлу (`<...>` → ADIF, `START-OF-LOG:` → Cabrillo, `[REG1TEST;1]` → попередження «EDI ще не підтримується»). Завжди створюється новий журнал — імпорт ніколи не зливається з наявним. Імпорти ADIF надходять як звичайні журнали, якщо тільки заголовок не несе `APP_LQ_CONTEST_ID`, записаний нашим власним експортом змагання (у такому разі журнал відновлюється як журнал змагання цього змагання). Імпорти Cabrillo завжди надходять як журнали змагань — див. розділ *Змагання* про те, як мітка `CONTEST:` порівнюється з вбудованим каталогом.
- **Експорт ADIF**: натисніть *Експортувати .adi* в заголовку журналу. Завантажується файл відповідно до **ADIF 3.1.7**. Заголовок декларує `ADIF_VER 3.1.7`, `PROGRAMID local-qso`, `PROGRAMVERSION` і `CREATED_TIMESTAMP` (UTC). Виведені поля QSO (коли не порожні): `CALL`, `QSO_DATE`, `TIME_ON`, `BAND`, `MODE`, `SUBMODE`, `PROP_MODE`, `GRIDSQUARE`, `BAND_RX`, `SAT_MODE`, `SAT_NAME`, `RST_SENT`, `RST_RCVD`, `COMMENT`, `STATION_CALLSIGN`, `OPERATOR`, `MY_GRIDSQUARE` — потім кожне додаткове поле ADIF, збережене при імпорті (див. нижче).
- **Експорт Cabrillo** описаний вище в розділі *Змагання* — доступний лише для журналів змагань (кнопка *Експортувати .cbr* з'являється в заголовку журналу, коли журнал має змагання).
- **Безвтратний двонаправлений обмін**: при ADIF імпорті будь-яке поле, яке застосунок не моделює в UI (наприклад, `NAME`, `FREQ`, `TX_PWR`, `DXCC`, `QSL_SENT`/`QSL_RCVD`, `POTA_REF`, поля `APP_*`), зберігається в QSO-зв'язку і при наступному ADIF експорті відтворюється дослівно. Таким чином, експорт файлу, який сам був імпортований, зберігає все.
- Довжина поля в ADIF трактується як кількість байтів UTF-8, як того вимагає специфікація, тому багатобайтний текст (наприклад, позивні з акцентами в `COMMENT`) розбирається коректно.

## Конфіденційність і дані

- Всі дані зберігаються в `localStorage` браузера під ключем `local-qso:v1`.
- Нічого нікуди не передається. Немає бекенду, немає API-запитів, немає телеметрії, немає аналітики.
- Очищення даних сайту в браузері, використання приватного/інкогніто-режиму або іншого браузера/пристрою означає новий порожній журнал — використовуйте *Експортувати .adi* для резервного копіювання.

## Теми

## Технічні примітки

- Односторінковий застосунок, ванільний HTML + CSS + JavaScript. Без фреймворків, без кроку збірки, без залежностей.
- Вихідні файли:
  - `index.html` — розмітка і мета-теги.
  - `style.css` — теми і макет (змінні дня/ночі, медіазапити для мобільних).
  - `app.js` — стан, збереження, рендеринг, парсер/серіалізатор ADIF, пошук префікса позивного → країна.
  - `favicon.svg` — вбудований SVG-фавікон.
  - `manifest.webmanifest` — Web App Manifest (назва, колір теми, область, значок), щоб застосунок був встановлюваним як PWA на мобільному і десктопі.
  - `service-worker.js` — service worker з пріоритетом кешу, який попередньо кешує кожен статичний файл при встановленні, витісняє старі кеші при активації і підтримує застосунок повністю в автономному режимі після першого відвідування. Реєстрація автоматично пропускається на протоколі `file://`, тому відкриття `index.html` безпосередньо з диска залишається коректним.
  - `i18n.js` — єдиний пакет, що підтримується вручну, який несе всі 28 мовних словників. Кожна мова — це самостійний IIFE, що присвоює `window.I18N[<lang>]` плоске відображення ключ→рядок. Блоки відокремлені коментарями заголовка `// ==== <lang> ====` — знайдіть (grep) один, щоб перейти до цієї мови. Об'єднано в один файл замість 28 окремих, оскільки файли перекладів дуже повторювані (однакові назви ключів, однаковий синтаксис заповнювачів), і gzip стискає весь набір значно краще, ніж 28 окремих потоків — заощаджує ~23 КБ при першому завантаженні і забирає 27 HTTP-запитів. `t()` і `applyLanguage()` у `app.js` обробляють пошуки (з резервною англійською) і обходять DOM, оновлюючи кожен елемент `[data-i18n*]`.
  - `contests.js` — єдиний пакет, що підтримується вручну, який несе всі 68 конфігурацій змагань. Кожне змагання — це самостійний IIFE, що присвоює `window.CONTESTS[<id>]` об'єкт конфігурації, що відповідає схемі (`{name, shortName, windows[], bands[], modes[], exchange[], duplicateRule, cabrillo}`). Блоки відокремлені коментарями заголовка `// ==== <id> ====` — знайдіть (grep) один, щоб перейти до цього змагання. Об'єднано в один файл замість 68 окремих, оскільки конфігурації змагань дуже повторювані (однакова схема, однаковий префікс `APP_LQ_*`, однакові назви полів заголовка Cabrillo), і gzip стискає весь набір значно краще, ніж 68 окремих потоків — заощаджує ~42 КБ при першому завантаженні і забирає 67 HTTP-запитів. Завантажується одним тегом `<script>` у `index.html` перед `app.js`, тому реєстр заповнений, коли будується спадний список Змагання.
- Перевірено на актуальних Chromium, Firefox і Safari (десктоп + iOS).
